# 认证核心与 WPF 的桥接

WPF 承担所有可见界面、编辑草稿、托盘与启动设置。独立 x86 C++ 进程复用原 `CProcess`，通过隐藏兼容窗口承接原线程、计时器及控件依赖。

```text
WPF 首页 / 设置 / 托盘
  → 私有匿名管道：账号 key、网卡 key、带序号命令和状态
    → C++ 隐藏兼容窗口
      → 原 CProcess、pcap、配置与锐捷 6.61 协议
```

## 保留的边界

- `Process.cpp`、`Process.h` 和 `Source/Other` 在此提交中不修改。
- `build-engine.ps1` 只在生成的编译单元中将两条界面 include 替换为 `EngineHost.h`；原认证函数保持原样。
- 解码函数和资源字符串从原文件提取。后台仍依赖 MFC 运行库，尚未完成引擎去 MFC。
- UI 请求仅传账号／网卡 key，后台读取 WPF 独立配置。密码不放入命令行或状态日志。
- 后台没有监听端口或共享命名管道，受父进程专属 Job Object 管理。
- START 前验证配置、驱动、设备和旧客户端运行状态。STOP 调用原 `endCert`；QUIT、管道关闭和前端退出结束私有后台，不主动发送 Logoff。
- `AccountN`、`DefaultAccount`、`DefaultAdapter`、`CertFlag`、`PackagePath` 保持原格式；未知项与附加字段保留。

## 新的桌面功能

页面与控件动画、账号／密码编辑、UI 状态、半秒延迟收起、当前用户开机运行均由 WPF 管理。热点选项是认证成功后的独立辅助流程，保存为 `[WpfOptions] HotspotAfterSuccess`，不改变旧协议字段；每次手动认证至多尝试一次，断开与退出可取消待完成动作。

## 验证与后续

.NET Framework 前端与独立 C++ 后台可从此提交构建。配置／密码兼容、离线后台、UI 草稿／保存／取消、动画和隔离启动项检查通过；用户已反馈认证、热点和界面运行正常。

自动检查只使用虚构账号、临时配置、离线请求、模拟动作或隔离子进程，不发送实际认证包，不登记真实系统启动项。真实系统登录启动和更多设备／校园网环境仍待验收；运行后自动认证尚未接通。

后续可在保持现有协议行为的基础上接入自动认证，并逐步移除后台对 MFC 窗口兼容层的依赖。
